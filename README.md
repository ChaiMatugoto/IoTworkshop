# 都市課題マップ

13のIoT課題を探して解決するワークショップ用アプリ。React + TypeScript + Vite + Tailwind CSSと、共有進捗用のSupabaseを使います。IoT機器・Googleスプレッドシートとの連携は参加者が作る課題です。

## ローカル起動

Node.js 22以上を推奨。

```sh
npm ci
npm run dev
npm test
npm run typecheck
npm run build
npm run preview
```

開発URLは http://127.0.0.1:5173 。Supabase未設定でもチーム名入力・街の探索・課題表示ができます。ポイントの獲得と共有には[初回設定](supabase/README.md)が必要です。

矢印キー / WASD・スマホの方向ボタンで移動。近づくと課題名と「Eキーで見る」が表示され、E・クリック・タップで開きます。×・Esc・Eで閉じ、入力中のEは文字入力を優先します。全体マップ・課題・ダイアログ表示中は移動を停止します。

## ポイントと運営

レベル1は7問×10pt、レベル2は4問×25pt、レベル3は2問×40pt、合計250pt。運営から受け取った正しい4桁コードで初回のみ加算します。DB側で検証・集計し、クライアントから得点を送信しません。運営画面 `#/admin` は共通パスワードで入場し、チーム名・合計点・完了課題を5秒ごとに更新します。一覧取得・全リセットはサーバー側でも共通パスワードを確認します。

## 編集場所

- `src/data/issues.ts`: 課題ID・位置・レベル・点数・タイトル・説明・使用部品・実装条件・場面。
- `scripts/task-codes.json`: 運営用の課題コード。公開用バンドルには含みません。
- `src/data/map.ts`: 2100×1575の座標、建物・川・橋・道路・通行判定。
- `src/components/CityMap.tsx`, `PixelSprites.tsx`, `BuildingVariants.tsx`, `IssueIllustration.tsx`: 街・主人公・場面別の独立したSVG素材。
- `src/components/IssuePanel.tsx`, `Progress.tsx`, `TeamSetup.tsx`: 課題・得点・参加UI。
- `src/hooks/useMovement.ts`: 時間差ベースの移動とタッチ操作。
- `src/storage.ts`: 端末の位置と旧保存データの復元。
- `src/hooks/useRemoteTeam.ts`, `src/lib/cloud.ts`: 共有サーバーとの接続。
- `src/components/AdminDashboard.tsx`: パスワード付きの運営一覧・自動更新。
- `supabase/migrations/001_workshop.sql`: DB・権限・得点処理。

描画と通行判定は共通の論理座標を使います。装飾の木・池・公園は通行可能。マーカーはLv.1紫、Lv.2青、Lv.3オレンジ。街の面積は当初の約3.5倍です。

## 保存の制限

進捗はSupabase、主人公の位置はlocalStorageの `urban-issue-map:v1` に保存します。匿名ログインのセッションもブラウザ内に保持します。ブラウザデータ削除・別端末ではチームを引き継げません。参加者のメールログインや端末引継ぎはありません。ネットワークが利用できない間はコードを提出できません。未設定時のローカルプレビューでは加点できません。既存の端末内進捗をサーバーへ自動移行しません。

## GitHub Pages

公開先は `ChaiMatugoto/IoTworkshop` です。PagesのSourceをGitHub Actionsにし、[接続用Variables](supabase/README.md)を設定してください。`.github/workflows/deploy.yml` がテスト・ビルド・デプロイします。公開はActionsから手動実行します。Viteは `GITHUB_REPOSITORY` から実際のリポジトリ名に合うbaseを算出し、`ユーザー名.github.io` では `/` を使います。カスタムドメインでは `VITE_BASE_PATH=/` で上書きできます。

## 検証

`npm test` で全13課題の点数・配置・到達可能性、保存復元・破損データ、DBのコード検証・二重加算防止・権限・リセットを確認します。DBテストのAuth・ハッシュ関数は代替実装です。実際のSupabaseログイン・通知・ブラウザでの連携確認はプロジェクト作成後に必要です。

## 管理者の全チームリセット

既存プロジェクトでは `supabase/migrations/002_admin_reset.sql` をSQL Editorで一度実行してください（初回構築でも001の後に002を実行）。管理者画面の「全チームをリセット」から確認欄に「リセット」と入力すると、その開催回のチーム名・得点・完了を全削除します。別開催回・課題・コード・管理者は維持します。参加者は5秒ごとの確認でチーム名入力に戻ります。オフラインの場合は接続復帰後に戻ります。匿名セッション自体は維持し、再登録できます。削除は取り消せません。

参加登録はチーム名のみです。既存のSupabaseでは `supabase/migrations/003_no_join_code.sql` をSQL Editorで実行してください。課題の4桁パスワードは維持します。

運営画面の認証解除には `supabase/migrations/004_public_admin.sql` をSQL Editorで実行します。参加画面には運営画面へのリンクを表示しません。

課題パスワードの `scripts/task-codes.json`、`.env.local`、運営用SQL・コード一覧はGitに含めません。GitHub PagesはActionsの「Deploy to GitHub Pages」から手動で実行します。サイトの予定URLは https://chaimatugoto.github.io/IoTworkshop/ です。

## 結果発表

管理画面の「結果発表を開く」、または `/#/admin/results` で発表画面を開けます。「結果発表 → 下位の順位 → チーム名・合計点・レベル別解決数 → 次の順位」の順に表示します。画面にはボタン・操作案内・スライド番号を表示しません。

クリック・右矢印・Space/Enterで次へ、左矢印で戻り、Homeで最初へ、Fで全画面を切り替えます。同点は同順位（1位・1位・3位）。画面を開いた時点の結果を固定し、再読み込みで取り直します。

## 管理者パスワード

既存プロジェクトでは `supabase/migrations/005_admin_password.sql` をSQL Editorで一度実行してください。管理画面と結果発表画面は共通パスワードを求めます。パスワードはブラウザの保存領域へ書き込まず、画面を再読み込みすると再入力が必要です。サーバーの一覧取得・全リセットも検証します。古い公開APIは削除します。005を適用してから新しいフロントエンドを公開してください。

## 管理者による正解登録

既存の005に続けて `supabase/migrations/006_admin_complete.sql` をSQL Editorで実行します。管理者画面の未完了のマスを右クリックし、メニューの「正解にする」を選択して、チーム・課題・点数を確認して登録します。DB側で管理者パスワード・開催回・チーム・課題を確認し、初回だけ加算します。参加者のパスワード提出と併用しても二重加算しません。参加者画面には通常5秒以内に反映します。開いている発表画面は結果を固定しているため、再読み込みしてから発表してください。

管理表の通常表示は「—」「✓」です。未完了マスの右クリック（キーボードではShift+F10）で正解登録メニューを開きます。Esc・外側クリック・スクロールで閉じます。

完了済みの「✓」も右クリックでき、「不正解にする」から確認後に未完了へ戻せます。`supabase/migrations/007_admin_incomplete.sql` を追加実行してください。合計点は残っている完了課題から再計算し、同じ課題の取り消しを繰り返しても二重減点しません。

## チーム詳細・正解順

`supabase/migrations/008_admin_team_details.sql` をSQL Editorで追加実行してください。管理者画面のチーム名の下にある「詳細」から、現在正解済みの課題を時刻の古い順に確認できます。課題名・レベル・点数・正解時刻（日本時間）を5秒ごとに更新します。既存の正解データも対象です。不正解への取り消しは除外され、再正解は新しい時刻になります。完全に同時刻の場合は課題ID順です。全リセット前の履歴や取り消した過去の履歴は保持しません。取得APIも管理者パスワードが必要です。

## チーム名変更・個別リセット

`supabase/migrations/009_admin_team_management.sql` をSQL Editorで追加実行します。管理表のチーム名の下に「名前変更」「リセット」があります。名前変更では正解・得点・正解時刻を保持し、参加者側のチーム名も5秒ごとの取得で更新します。個別リセットは対象チームの登録・完了・正解履歴だけを削除し、オンラインの参加者は通常5秒以内にチーム名入力に戻ります。他チーム・別開催回・参加者の匿名ログインは維持し、再登録できます。削除は確認後に実行し、取り消せません。参加者画面の「課題一覧」「最初から」は表示しません。

## センサ・部品一覧

ヘッダーの「センサ一覧」リンク、または `/#/parts` から、10種類の部品のイラスト・基板上の表記・できることの説明を確認できます。10種類をひとつの一覧にまとめています。説明は `src/data/parts.ts`、画像は `public/parts/` のSVGです。実物の写真がある場合は差し替えできます。外部API・SQLの追加設定は不要です。

部品一覧の英語表記は実基板の文字に合わせています（PotentioMeter等の大文字小文字も保持）。Spareは表示せず、傾きスイッチは基板ごと傾ける説明にしています。

## ヒント
ヘッダーの「ヒント」、または `/#/hints` から、レベル1〜3のヒントを開閉できます。レベル1にはChatGPTの項目記入からArduino IDEへの書き込みまでのガイドがあります。項目の説明は `src/data/levelOneGuide.ts`、手順は `src/components/LevelOneGuide.tsx` で編集できます。レベル2のGAS連携ガイドは `src/components/LevelTwoGuide.tsx` から編集できます。レベル3は仮の文章で、`src/data/hints.ts` から編集できます。

課題画面は住民との会話を「次へ」で進め、お願いと目指すシステムを確認する形式です。会話・お願い・目標文は `src/data/residents.ts` で編集できます。「パスワードを入力」を押すと、同じ位置に4桁入力欄が表示されます。会話は矢印キーでも進められ、課題マークの近くに表示されます。
